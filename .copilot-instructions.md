# Copilot Instructions

## Project Context
- Flutter application for GO board game
- Multiple board sizes (9x9, 13x13, 19x19)
- Target platforms: Android, iOS
- Main features: offline play, online multiplayer

## Code Style
- Use Dart best practices
- Follow Flutter widget patterns
- Use named parameters for widget constructors
- Add documentation for public APIs

## File Structure
- lib/
  - models/ (data structures)
  - screens/ (full screen widgets)
  - widgets/ (reusable components)
  - services/ (external APIs)
  - assets/ (resources)

## Naming Conventions
- ScreenName for screen files (e.g., HomeScreen)
- snake_case for file names
- camelCase for variables and methods
- PascalCase for classes

## Code Quality Standards
- Write self-documenting code with clear variable and function names
- Keep functions small and focused (single responsibility)
- Maximum function length: 20-30 lines
- Maximum file length: 300-400 lines
- Use early returns to reduce nesting
- Avoid deep nesting (maximum 3 levels)
- Extract complex logic into separate methods
- Use const and final appropriately
- Implement proper error handling

## Documentation Requirements
- Add doc comments for all public APIs using /// format
- Include @param and @return tags in method documentation
- Document complex algorithms with step-by-step explanations
- Add example usage in documentation when appropriate
- Document any assumptions or limitations
- Keep comments up-to-date with code changes
- Use TODO comments with JIRA/GitHub issue numbers
